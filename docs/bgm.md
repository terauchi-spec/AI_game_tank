# Menu background music

`assets/audio/bgm/stahlmarsch_zum_sieg.mp3` is the supplied 60.160-second MP3. It plays once across title, skill selection and stage selection without restarting between those screens. Other screens and hidden/blurred pages pause it. Returning to an eligible screen resumes its position; once ended, it stays ended until the next result screen or page reload.

Browser autoplay restrictions require the first trusted pointer/key interaction before audible playback. No additional start button is added. Music now uses AudioBufferSourceNode on the same AudioContext as SE, without an HTMLAudioElement or media playback session. BGM gain is 0.184 (80% of the previous 0.23) and SE gains are unchanged. Playback errors cannot block the game or create automatic retry loops. The main render loop only checks playback state; it does not restart a playing track.

Opening a new mission result screen resets the theme to the beginning and waits for active result/success/failure SE voices to finish. Voice removal on the actual Web Audio `onended` event releases the wait, rather than a fixed timer. If the result SE is unavailable and no voice plays, BGM can start immediately. Both success and failure results play the theme once; opening/closing the achievement overlay does not restart it. An asynchronous load cannot start music while result SE is still playing or after leaving eligible screens.

Only one BGM fetch/decode can run. One decoded song buffer is retained separately from the SE LRU (about 20.2 MiB at 44.1 kHz stereo, or 22.0 MiB at 48 kHz). At most one music source plays, using a shared gain. Pausing saves the offset against AudioContext.currentTime, detaches the completion handler and stops/disconnects the source; resuming starts a new source at the saved offset. Natural completion never repeats. The MP3 file itself is unchanged. Native Web Audio output follows the same device audio policy as SE; iPhone mute-switch behavior requires device verification.
